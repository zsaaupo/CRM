# Django frontend foundation

See [ACCESS_CONTROL.md](ACCESS_CONTROL.md) for the site-wide permission policy
and setup for delegated administrators.

The initial pages use Django template inheritance, Tailwind's browser CDN,
and namespaced vanilla JavaScript. Signup, verification, and resend forms use
`fetch()` to call the JSON APIs without reloading on validation errors. The login
page establishes a Django session and redirects to a protected dashboard.

## Structure

- `account/api_urls.py` and `account/api_views.py`: JSON API routes and views.
- `account/page_urls.py` and `account/page_views.py`: HTML page routes and views.
- `templates/base.html`: shared HTML document and stylesheet loading.
- `templates/layouts/auth.html`: shared authentication page layout.
- `templates/layouts/dashboard.html`: sidebar, top bar, user menu, and logout form.
- `templates/includes/`: reusable header and Django messages.
- `account/templates/account/`: namespaced authentication and workspace templates.
- `static/js/api.js`: shared JSON fetch helper with CSRF, HTTP errors, and timeouts.
- `account/static/account/js/auth.js`: form validation, loading states, field errors,
  password visibility, signup/login, add-user, verification, and resend interactions.
- `account/static/account/js/workspace.js`: avatar dropdown, mobile navigation,
  expandable Users menu, and fetch-based session logout.
- `account/static/account/js/users.js`: fetch user directory, search, pagination,
  safe text rendering, and loading/empty/error states.
- `static/css/custom.css`: plain CSS for typography, selection, and the skip link.
- `static/images/`: shared image assets.
- `staticfiles/`: deployment output generated by `collectstatic`; excluded from Git.

## Tailwind CDN

`templates/base.html` loads Tailwind once for all pages:

```html
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
```

The browser generates Tailwind utilities as the pages load. Add utility classes
directly to templates; there is no local compiler, CSS watcher, or Node.js setup.
Internet access to jsDelivr is required for Tailwind styling. Keep ordinary custom
CSS in `static/css/custom.css`; it is loaded after the CDN script and preserves
the shared typography and accessibility styles.

## Preview pages

The Add user form includes an optional profile image picker and submits through
the shared `postFormData` helper, preserving session and CSRF protection. The
browser sets the multipart boundary. Empty optional dates are omitted and image
validation errors appear beside the file picker. Signup has no image upload.
User rows display the API's `image` URL in their existing avatar position. The
profile, dashboard and account menu share `includes/avatar.html`. Images cover
the avatar area; existing name initials remain the fallback for missing images
or image load failures.

```powershell
.\venv\Scripts\python.exe manage.py runserver
```

- `/` redirects to the dashboard, which requires login.
- `/account/login/` renders the login page; success navigates to `/dashboard/`.
- `/dashboard/` shows the signed-in user's account overview.
- `/account/profile/` shows that user's profile details.
- `/account/add-user/` creates an active user through the authenticated API.
- `/account/users/` shows the authenticated user directory.
- `/account/roles/` lists roles with edit, permissions and delete icon actions.
- `/account/roles/<id>/permissions/` edits a role's model permissions.
- `/account/signup/` renders `account/signup.html`.
- `/account/verify-otp/` renders `account/verify_otp.html`.
- Existing JSON endpoints stay under `/account/api/`.

Signup success redirects to the verification page. Only the email address is kept
in tab-scoped `sessionStorage` to prefill that page; passwords and OTPs are not
stored in browser storage. If storage is unavailable, the email can be entered
manually. Verification activates the user and displays a success state; it does
not automatically log in. A link takes verified users to the login page. Resend
uses the email field and replaces the old code.

The dashboard sidebar contains Dashboard and an expandable Users section with
Add user and User list links. The Users section stays expanded on those pages,
with the current page highlighted. The add-user form sends a CSRF-protected
fetch POST, shows field validation errors, and redirects to the user list on
success when permitted, or to the dashboard otherwise. The list calls `GET /account/api/users/`, supports search and 20-user
pages, and displays active/inactive status. Both new pages require login.
The user list page and API additionally require `auth.view_user`, inherited from
the user's assigned group or granted directly. In the role permission matrix,
select Read for the user model in the auth app. Active superusers retain access.
The User list sidebar link is hidden without permission. Direct navigation by
authenticated users without permission returns 403. Permission changes apply on
the next request; a list API 403 displays an access-denied message. All management
pages and APIs enforce the shared policy in `account/permissions.py`. Navigation
and action buttons follow that policy. Dashboard, own profile and logout require
login only; authentication and verification pages remain public.

The top-right initials avatar opens
Profile and Logout actions. Mobile navigation opens as a drawer and closes with
Escape or the backdrop; keyboard focus stays inside the drawer while it is open.
Logout uses a CSRF-protected POST and clears the session. Dashboard/profile pages
are not cached, and browser-history restoration triggers an authentication recheck.

Authorized access administrators see an Assign role action with a shield/check
permission icon on user rows.
It opens the protected `/account/users/<id>/assign-role/` page, showing the target
user, current role and a single-role dropdown. Saving sends the user and group IDs
to `POST /account/api/assign-group/` with CSRF protection and redirects to the user
list on success. Errors preserve the selection. With no roles, saving is disabled
and authorized creators see a link to Add role. Cancel returns to the user list
without saving.

The Add role button with a plus icon sits in the page heading above the role table,
matching the Add user button on the user list page.
It opens the protected `/account/roles/add/` page. The form uses `auth.js` to
submit the role name to `POST /account/api/groups/` with CSRF protection, displays
validation errors, and redirects to the role list after creation when permitted,
or to the dashboard otherwise. Cancel follows the same destination. New roles
start without permissions.

Roles & Permissions expands to Role list. `roles.js` loads groups, handles the
rename dialog and confirms deletion. `permissions.js` renders a checkbox matrix
with one CRUD row per model, current group assignments, and any custom
permissions. Save permissions sends checked IDs with a CSRF-protected PUT and
redirects to the role list on success. Errors preserve checkbox selections;
controls are disabled while saving. Reset restores the loaded assignments.

Use `{% url %}` for page and API routes, and `{% static %}` for asset URLs.
Use `{% csrf_token %}` in forms and send its value as `X-CSRFToken` when adding
JavaScript submissions. Keep server validation in the serializers and views.

For deployment, run `manage.py collectstatic`; configure your hosting
to serve `STATIC_ROOT`. Django's development static-file server is for local use.
